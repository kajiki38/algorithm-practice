データ構造 — スタック・キュー・ハッシュ

アルゴリズムは「データをどう持つか」で決まる。まずは 3 つの基本の入れ物を自分の手で操作して、 取り出される順番と探すのにかかる手間の違いを体に入れよう。

このページで学ぶこと

データ構造とは、データの「入れ物」のこと。 同じ 100 個のデータでも、山積みにするか、行列に並べるか、ラベル付きの棚に仕分けるかで、 「取り出す」「探す」にかかる手間がまったく変わる。 道具箱と同じで、入れ物の形にはそれぞれ得意な操作がある —— それを知っていると、あとで学ぶアルゴリズムが「なぜその入れ物を使うのか」まで見えるようになる。

このページで触るのは 3 つ。スタック（本の山: 上にしか置けない・上からしか取れない）、 キュー（レジの行列: 並んだ順に出ていく）、 ハッシュテーブル（ラベル付きの棚: 計算で置き場所が即わかる）。

このページの使い方

  1. 1
    スタックに値を 3 つ push（積む）してから 3 回 pop（取り出す）。入れた順と逆に出てくることを確認しよう。
  2. 2
    キューでも同じことを。今度は入れた順のまま出てくる。この違いがすべての出発点。
  3. 3
    違いが体に入ったか、予想クイズでチェック。
  4. 4
    ハッシュテーブルに「サンプル 8 件を投入」して、キーが計算で棚に振り分けられる様子を見る。そのあと検索して比較回数がリストよりずっと少ないことを確認。
つまずいたら: 用語ミニ辞典
push / pop（プッシュ / ポップ）
スタックに「積む」「取り出す」操作の名前。プログラミングの世界の共通語なのでこのまま覚えて損はない。
enqueue / dequeue（エンキュー / デキュー）
キュー（queue = 行列）に「並ぶ」「先頭から出る」操作の名前。
LIFO / FIFO
Last-In First-Out（最後に入れたものが最初に出る = スタック）と First-In First-Out（最初に入れたものが最初に出る = キュー）の略。
ハッシュ関数
キー（文字列など）から「何番の棚に入れるか」を計算で決める仕組み。このページでは「文字コードの合計を棚の数で割った余り」というシンプルな式を使っている。
衝突（しょうとつ）
違うキーがたまたま同じ棚に入ること。棚の中に鎖のようにぶら下げてしのぐ（チェイン法）。衝突が増えると検索が遅くなる。
O(1) と O(n)
計算量ページで学んだ記号。O(1) は「データが何個あっても手間は一定」、O(n) は「データの個数に比例して手間が増える」。
